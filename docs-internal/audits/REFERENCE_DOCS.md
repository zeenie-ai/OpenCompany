## Separate code gaps and acceptance limits

- **Active-account enforcement:** HTTP middleware and WebSocket admission verify JWT claims without the active-user lookup used by auth status/me. Add isolated inactive-account HTTP/handshake tests before choosing enforcement and already-connected-socket policy. Documentation now states the limitation.
- **REST ownership:** new REST-created graphs use placeholder owner `owner`; updates preserve existing ownership. Trusted HTTP identity propagation needs a separate implementation and creation/update/legacy authorization tests.
- **Google Maps credentials:** the executor injects a saved `api_key`, but the three location plugins' extra-ignoring Params omit it and pass only `model_dump()` to the service. The service reads that dumped key or the environment fallback, so the saved-key-only path is not established. This peer-review finding was reported to the lead for the integration cards/skills and main gap list; no code was changed.
- **Standalone chat tuning:** `AIService.execute_chat` does not forward all declared model Params, and enabling thinking with an unset nullable budget can fail before dispatch. The native guide and model cards record these source-backed gaps; no runtime repair is implied.
- **RLM limit exposure:** the service reads snake_case limits but `RLMAgentNode.Params` is the shared extra-ignoring schema. Except shared `max_tokens`, custom RLM limits/options are not exposed through the node contract. A separate schema/product decision and propagation tests are needed.
- **Known compatibility gaps remain visible:** Codex unpooled runs are rejected by `AICliSession`; Twitter Receive is explicitly refused because it lacks a producer/poll factory; some direct canvas push waits are not reached by current producers. These were not silently repaired or declared operational.
- **Reset cleanup:** the previously discussed cleanup change is committed in this baseline; preserve its accurate current documentation rather than repeating it as an unfixed earlier-HEAD gap.
- Vendor command/permission/billing semantics, publisher/platform acceptance, real browser/mobile/OAuth operation and historical performance measurements require independent verification in their appropriate environment. No such result is implied by this ledger.
