## Findings reported to the lead

- Setup native-provider keys must use approved connections, not ambient OPENAI/ANTHROPIC/GOOGLE-AI environment variables; Google Maps retains its explicit executor environment fallback. The lead corrected this guidance. Peer review also found that saved Maps keys injected before plugin Params validation are dropped by the location plugins; their service's environment fallback can mask that separate code gap, which was reported to the lead.
- CLI-service introduction must distinguish backend-supervised local daemons from operator-managed external services. Persisted Temporal history is not a promise to retain every execution forever; compatibility resets and retention cleanup are separate boundaries.
- The speech implementation RFC's three-attempt/base64-only constraint is a historical pre-implementation baseline. Current media nodes use file references and PayloadsTooLarge is non-retryable; the lead added current-status framing.
- Email controlled polling uses setup_service/fetch_ids/fetch_detail/post_emit hooks and one-cycle Activities. Credentials resolve during each Activity setup, and the controller receives bounded event/seen-id results. Its interactive first-result loop is a distinct path.
- Gateway1Password support is currently absent from this router/credential implementation. Describing per-call1Password resolution itself as impossible would conflict with the ordinary provider runtime resolver.

## Remaining external and artifact boundaries

- Cloud costs, resource sizing/boot-time measurements, public installer/release availability, current GitHub Security settings and advisory state were not verified from repository code.
- Pinned provider/CLI SDK adapters establish the local integration contract, not every live upstream endpoint, permission, billing behavior or current license tier.
- SVG/PNG/logo documents are conceptual or historical artifacts. Local references and source geometry/test entrypoints were reviewed; no rendered fidelity or visual equivalence claim was made.
- The two shipped SKILL.v1.md files are active opt-in defaults selected by services/skill_defaults.py, not historical snapshots. Their semantic node/skill audit is recorded by the core-node lane.
