# Core node and skill audit

Status: source-backed audit snapshot, 2026-11-02. Baseline:
`56d4154e713845d93124875b271144acac8d26cd`, isolated documentation worktree.

Covers **88 supported node types**, **99 node-operation entries** (75 distinct
source operations) and every fixed selector branch, **31 default skills**, the active Process Manager v1 variant,
and the skill-authoring guide. The sibling integration audit covers the other
families. Counts describe this snapshot and are not fixed CI expectations.

“Reviewed” means node-specific static comparison of declaration, operation
body/dispatch, execution path and card. It does not mean a live provider/device
was exercised or every backend branch executed. Sources, existing code gaps
and actual offline validation are distinguished below.

## Shared independent execution contracts

- **D/G: direct/graph.** [WorkflowService.execute_node](../../server/services/workflow.py#L202)
  assembles graph/workspace context, special-cases new Coding Agent/Pi admission,
  then calls [NodeExecutor](../../server/services/node_executor.py). Direct Run
  still needs required saved scope, credentials and connections. Passive config
  nodes are graph bindings, not automatically scheduled main-flow actions.
- **Schema and result.** [BaseNode](../../server/services/plugin/base.py)
  validates Params, selects the operation, resolves declared connections and
  validates/serializes Output into the standard envelope. Unexpected tracebacks
  go to logs, not a public traceback field. [ToolNode](../../server/services/plugin/tool.py)
  returns flat payloads. Output defaults and extra policy can add/retain fields;
  a raw service result is not necessarily the final serialized shape.
- **T: agent tool.** execute_as_tool validates split ToolInput independently
  from persisted Params, or uses the compatible validated merge for old tools.
  Locked fields and trusted caller/workflow/node scope cannot be supplied by
  the model. Node type, callable name and visual alias differ. Shared metadata
  emits output-tool for invokable tools even when the concrete class only
  declares main/model handles. A hidden Run button alone does not prohibit a
  valid direct operation; explicit refusal/scope requirements determine that.
- **A: Temporal.** [MachinaWorkflow](../../server/services/temporal/workflow.py)
  graph scheduling normally uses its shared 24-hour Activity-attempt timeout
  and plugin retry policy. For workspace_task under its versioned patch it
  substitutes plugin start/heartbeat policy. [AgentWorkflow](../../server/services/temporal/agent_workflow.py)
  tool calls separately use captured plugin policy. A class timeout alone does
  not describe every caller. Native agents/Pi and opaque CLI/RLM paths differ.
- **Control and effects.** Cooperative Stop closes future admission and drains
  admitted work/bookkeeping; Resume continues that execution. Cancellation and
  Reset are separate and cannot undo a remote mutation. Approval enforcement
  depends on the caller: BaseNode.as_activity and the in-process plugin tool
  dispatcher invoke approval checks; declarations alone do not prove that every
  direct path does. Sending-rule plugins retain their own restrictions. The
  [approval contract](../chat_protocol.md#approvals) describes held-send behavior;
  compare each route with the actual [approval check](../../server/services/approvals/tool_calls.py).
  Readonly/destructive metadata is not security isolation. Retry/idempotency/
  uncertain outcomes must be assessed for each operation.
- **Triggers.** [TriggerNode.execute](../../server/services/plugin/trigger.py)
  owns direct one-shot waits/polls; stub wait operations are not called. Deployed
  controlled triggers are definitions and accepted Signal queues. Process-local
  canvas waits and deferred HTTP futures gain no durable delivery guarantee.
- **W: Workspace.** Explicit browser/mobile workspace_task declarations use
  separate ownership, admission and cancellation identities from deployment
  Stop/Resume. Registry presence, palette/Hire allowlists, hidden controls,
  platform support and runtime readiness remain distinct availability facts.

## Known code gaps retained

Documentation changes do not implement these runtime fixes:

- File Downloader ignores canonical output_dir/max_workers/skip_existing for
  retained legacy extras; Text Chunker ignores chunk_size for legacy chunkSize.
- File Downloader URL-decodes a basename before an unchecked output-directory join; encoded separators can escape that directory, and the response body has no byte cap.
- Maps create/nearby key mismatches remain. All three Maps nodes discard injected api_key through Params(extra="ignore"); their helpers ignore preserved raw context, so saved-credential-only calls fail while the GOOGLE_MAPS_API_KEY fallback can mask the gap. Nested service results differ from declared optional output fields.
- HTTP Scraper max_pages, Proxy Request follow_redirects, Proxy Status
  provider_name and Webhook Response headers are declared but unused.
  Proxy retries may repeat mutation requests; a webhook sent flag does not
  prove that a pending process-local HTTP future existed.
- Text Generator nonstatic sources and File Handler type-specific processing
  are unimplemented. Python Executor timeout is unenforced, exec blocks its
  loop and restricted builtins are not a security boundary; explicit/importing
  helpers and named exceptions are unavailable.
- Standalone chat exposes tuning fields that execute_chat never forwards (top_p/top_k/penalties/response_format/safety_settings); thinking_enabled with a dumped null thinking_budget can fail before dispatch. Adaptive Anthropic and empty Cerebras thinking policies are documented as configured behavior.
- RLM service limits mostly are not forwarded by shared node Params. Opaque
  RLM/CLI/mobile effects are not native per-tool model-turn checkpoints.
