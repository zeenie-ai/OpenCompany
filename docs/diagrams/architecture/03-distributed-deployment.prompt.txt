Architecture constraints (do not add them all as small prose; honor them in topology and brief callouts):
- Distributed mode requires shared PostgreSQL, external Temporal, native-agent and per-type dispatch, unique browser replica identity/trusted origin, one backend process per replica, and 1Password service-account authentication.
- Standalone workers refuse local mode and default to the same configured Temporal address, namespace and task queue as the backend. Generic workers exclude process-local Browser activities.
- Shared database rows contain browser ownership, route and fencing metadata, not live sockets or daemon state. The original owner retains the browser/profile. Owner loss is not automatic transfer to another machine.
- Cross-worker file access requires an explicitly suitable workspace-storage arrangement. This diagram does not imply PostgreSQL contains workspace file bytes.
- Distributed credential preflight rejects inline, OAuth, CLI-managed and unsupported machine-local connections. Not every local integration can be moved to generic workers.
- The remote relay transports chat-run events and selected lifecycle broadcasts. It is not a universal durable event bus.
- The shared mobile capability requires installation-owner authorization and Android runtime/queue prerequisites. It is not an arbitrary browser-owner replica task.
- Single-container Docker is a separate supported local recipe. Merely scaling Compose does not establish this distributed configuration.
