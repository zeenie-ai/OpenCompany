# Integration and independent-node evidence

Baseline: committed56d4154e713845d93124875b271144acac8d26cd, reviewed2026-11-02.
Method: per-plugin declarations, Params/Output and operation/selector branches were compared with every listed card. Shared service helpers, source-defined preconditions and side effects were inspected. This is static code evidence, not live-provider/device validation.

## Shared execution contracts

Direct Run can accept explicit parameters without a saved workflow for simple utilities. Each node's required saved scope, connections, credentials and workspace context must be checked separately; independence from Home does not waive those node-specific requirements. Agent tools use their actual connected callable, saved settings and approval policy; split ToolInput/config schemas must remain separate.
Triggers have distinct one-result direct waits/polls and durable controlled-deployment admission. A dummy wait method is not the listening implementation. Rendering hints and a hidden Run button do not establish execution support.
Cooperative Stop, direct cancellation and Reset are distinct. Graph versus agent-tool timeout selection differs; see the [core contracts](CORE_NODES.md) and [workflow control](../temporal-workflow-control.md). Ordinary file writes do not create a specialized Workspace task. Browser Workspace task admission/ownership is separate.
Base evidence: [BaseNode](../../server/services/plugin/base.py), [TriggerNode](../../server/services/plugin/trigger.py), [polling](../../server/services/plugin/polling.py), [webhooks](../../server/services/events/triggers.py), [NodeExecutor](../../server/services/node_executor.py).
